# Profile stats and cards: setup and maintenance

## Activity tiles (automated)

The four tiles in the README's Activity section are generated daily by
[.github/workflows/update-stats.yml](../.github/workflows/update-stats.yml),
which runs [scripts/update_stats.py](../scripts/update_stats.py). The images are
published to the `stats` branch, so `main` stays free of bot commits.

| Tile | Scope (last 12 months) | Source |
|---|---|---|
| Contributions | All repositories | GitHub's own count, including private work the token cannot read (for example an employer's). The "incl. N private" figure is GitHub's anonymous private count |
| Commits | Repositories I own, public and private | Commits authored by me on each repo's default branch |
| Pull requests | Repositories I own | PRs I opened, and how many of those were merged |
| Active repos | Repositories I own | Repos pushed to |

The Contributions tile only appears when private contributions are enabled on
the profile; otherwise it is hidden, because GitHub would silently omit private
work and the number would mislead.

Not included: issues, and per-type commit and pull request counts for
repositories owned by other accounts or organisations. GitHub only reports
private activity as one combined number, and a read-only token owned by this
account cannot read other owners' private repositories. The Contributions
tile still counts that work, with no names or details.

## One-time setup

1. **Private contributions.** On the profile page, open *Contribution settings*
   and turn on *Private contributions*. This shows anonymous counts only.
2. **Create a read-only token.** GitHub, *Settings, Developer settings,
   Personal access tokens, Fine-grained tokens, Generate new token*.
   - Resource owner: `azizz7`
   - Repository access: *All repositories*
   - Repository permissions, all *Read-only*: *Contents*, *Pull requests*
     (*Metadata* is added automatically)
   - Expiration: 1 year
3. **Store it.** In this repo: *Settings, Secrets and variables, Actions,
   New repository secret*. Name it `STATS_TOKEN`.
4. **First run.** *Actions, Update stats, Run workflow*. The tiles appear
   on the `stats` branch and in the README.

## Maintenance and failures

- Renew the token before it expires and update the `STATS_TOKEN` secret.
  Expiry shows up as a failed run.
- On any API error, rate limit exhaustion or malformed data the script exits
  non-zero and publishes nothing. The last good tiles stay in the README and
  GitHub's failed-run notification reaches the repo owner.
- The workflow runs only on schedule and manual trigger, never on pull
  requests, so the secret is never exposed to forks.
- Run locally for a quick check: `STATS_TOKEN=$(gh auth token) python3 scripts/update_stats.py --out /tmp/stats`

## Project cards (manual, rarely changes)

The four cards in Selected work are generated from the project list in
[scripts/build_cards.py](../scripts/build_cards.py). Edit that list and run
`python3 scripts/build_cards.py`, then commit the updated SVGs in `assets/cards`.
Each card links to a repository or live site from the README.

## Profile views counter

The "Profile views" badge comes from komarev.com's
[github-profile-views-counter](https://github.com/antonkomarev/github-profile-views-counter).
It counts page loads (hits) made through GitHub's image proxy, not unique
people, and it cannot see visitor IPs or usernames. If the service is down the
badge shows its alt text and the rest of the page is unaffected. There is
nothing to configure or renew. To reset the count, use the reset page linked
from that project's README.
